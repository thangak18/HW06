# BUG-FR02-001: Plaintext Password Disclosed in Successful Login Response

## Requirement

- **Normative sources:** `api_specification.md` §1.2 (`POST /api/login` returns a JWT plus user information), SRS §9 `SEC-01` (passwords must not be stored as plaintext), and the assignment's security/schema-testing requirement.
- **Oracle:** A successful login response must not disclose a reusable plaintext credential. The observed `user.password` value equals the account's plaintext credential, exposing it to clients and corroborating the SEC-01 storage defect.

## Related Test

- **ID:** `FR02-AI-028`
- **Postman path:** `04 - Security and Token Integrity / FR02-AI-028 - Sensitive Data Exclusion (Password Omission)`

## Environment and Preconditions

- Host: `http://localhost:3000`
- A fresh registered user exists.
- Runner: Newman 6.2.2 and Postman Desktop 11.89.0.
- All requests include `X-Student-Id: 23127259`.

## Reproduction

1. In Postman Desktop, select environment `FR02-local`.
2. Execute `FR02-AI-028` in `FR02_Login_Account_Lockout`.
3. Observe HTTP `200` and the organically failed password-omission assertion.
4. Inspect the response locally if needed; do not publish the returned JWT.

## Expected

- HTTP success with JWT plus non-sensitive user information.
- No plaintext password or password hash is returned.

## Actual

- HTTP `200 OK`.
- `user.password` is present and equals the account's reusable plaintext password.

## Severity

**HIGH** - credential disclosure through normal login can leak passwords through clients, logs, screenshots, and network intermediaries.
