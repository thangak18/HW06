# BUG-FR02-001: Plaintext Password Disclosed in Successful Login Response Profile

## Requirement
- **Specification Source:** `api_specification.md` §2.1 (`POST /api/login` Success Contract) & [ADDITIONAL-SEC] (Response Data Sanitization / OWASP API3:2023)
- **Contract Clause:** A successful authentication response must return a JWT token and a user profile object containing only public profile attributes (`id`, `name`, `email`, `role`). Sensitive credentials (plaintext password or hash) MUST NOT be exposed in API responses.

## Related Test Case
- **Test Case ID:** `FR02-AI-028`
- **Traceability Path:** `04 – Security and Token Integrity / FR02-AI-028 – Sensitive Data Exclusion (Password Omission)`

## Environment
- **Target Host:** `http://localhost:3000`
- **Component:** EShop Backend API (`server.js`)
- **Runtime:** Node.js v20.x, SQLite3
- **Runner:** Newman v6.2.2 / Python requests

## Preconditions
- A registered user account exists in the database (e.g. `user@eshop.com`).

## Reproduction Steps
1. Send a standard `POST /api/login` request with valid registered credentials:
   ```bash
   curl -s -X POST http://localhost:3000/api/login \
     -H "Content-Type: application/json" \
     -d '{"email": "user@eshop.com", "password": "User1234!"}' | jq .
   ```
2. Inspect the returned JSON payload inside the `user` property object.

## Expected Result
- HTTP `200 OK`
- JSON response structure:
  ```json
  {
    "message": "Login successful",
    "token": "<JWT_STRING>",
    "user": {
      "id": 1,
      "name": "Regular User",
      "email": "user@eshop.com",
      "role": "user"
    }
  }
  ```
- The `user` object MUST NOT include the `password` property.

## Actual Result
- HTTP `200 OK`
- The `user` object discloses the user's plaintext password:
  ```json
  {
    "message": "Login successful",
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "user": {
      "id": 24,
      "name": "Regular User",
      "email": "user@eshop.com",
      "password": "User1234!",
      "role": "user",
      "login_attempts": 0,
      "locked_until": null
    }
  }
  ```

## Reproducibility
- **100% (Deterministic across all test runs and standalone cURL/Python invocations)**

## Severity
- **HIGH**

## Severity Rationale
- Disclosing plaintext passwords in API responses compromises user credential confidentiality over the network, exposes passwords to client-side caching/logging layers, and violates OWASP API Security Top 10 (API3:2023 Broken Object Property Level Authorization).
