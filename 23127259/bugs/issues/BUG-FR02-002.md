# BUG-FR02-002: Account Remains Locked Beyond Documented 30-Second Lockout Duration

## Requirement
- **Specification Source:** EShop SRS §2 [FR-02] (User Login & Account Lockout)
- **Specification Clause:**
  > "If consecutive failed attempts >= 3, temporarily lock account for 30 seconds. After 30 seconds, the account must automatically unlock and accept authentication with valid credentials."

## Related Test Case
- **Test Case ID:** `FR02-AI-021` (and `FR02-AI-024`)
- **Traceability Path:** `03 – Lockout Boundary and State Progression / FR02-AI-021 – Post-Expiration Lockout Timing Boundary T=32s`

## Environment
- **Target Host:** `http://localhost:3000`
- **Component:** EShop Authentication State Engine
- **Runtime:** Node.js v20.x, SQLite3
- **Runner:** Newman v6.2.2 / Python requests

## Preconditions
- A registered user account exists with clean initial state.

## Reproduction Steps
1. Verify account authenticates initially with valid credentials (HTTP 200 OK).
2. Trigger account lockout by submitting 3 consecutive incorrect passwords to `POST /api/login`.
3. Confirm account transitions to locked state on 3rd attempt (returns HTTP 403 Forbidden).
4. Wait 36 seconds ($T \ge 35	ext{s}$, strictly exceeding the documented 30-second duration).
5. Submit valid credentials for the account:
   ```bash
   curl -s -X POST http://localhost:3000/api/login \
     -H "Content-Type: application/json" \
     -d '{"email": "lockout_user@eshop.com", "password": "CorrectPassword123!"}'
   ```

## Expected Result
- After the 30-second temporary lockout interval elapses, submitting valid credentials must successfully authenticate:
  - HTTP `200 OK`
  - JWT token and user profile returned.

## Actual Result
- SUT returns HTTP `403 Forbidden`:
  ```json
  {
    "error": "Tài khoản đã bị khóa. Vui lòng thử lại sau."
  }
  ```
- The account remains locked indefinitely and never automatically recovers without direct database modification.

## Reproducibility
- **100% (Deterministic across Newman timing suites and Python verification scripts)**

## Severity
- **HIGH**

## Severity Rationale
- Completely denies legitimate users access to their accounts following a temporary lockout. Because accounts never auto-unlock after 30 seconds, any user subjected to 3 failed attempts is permanently locked out (Denial of Service).
