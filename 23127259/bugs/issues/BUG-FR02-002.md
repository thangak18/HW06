# BUG-FR02-002: Account Remains Locked Beyond the 30-Second Duration

## Requirement

- **Normative source:** EShop SRS §2, FR-02.
- **Oracle:** After three or more consecutive failed logins, the account is temporarily locked for 30 seconds. Valid credentials must be accepted after that interval.

## Related Test

- **ID:** `FR02-AI-021`
- **Postman path:** `03 - Lockout Boundary and State Progression / FR02-AI-021 - Post-Expiration Lockout Timing Boundary T=32s`

## Environment and Preconditions

- Host: `http://localhost:3000`
- A fresh registered account begins unlocked.
- Runner: Newman 6.2.2 and Postman Desktop 11.89.0.
- All requests include `X-Student-Id: 23127259`.

## Reproduction

1. Trigger the account's lockout through the FR02 lifecycle sequence.
2. Wait 32 seconds, exceeding the specified 30-second interval.
3. Submit the correct credentials through `FR02-AI-021`.
4. Observe the response and failed assertion.

## Expected

- HTTP `200 OK` after expiration.
- JWT plus user information is returned.

## Actual

- HTTP `403 Forbidden`.
- API body reports that the account remains locked.

## Severity

**HIGH** - a temporary protection becomes an indefinite denial of service for a legitimate user.
