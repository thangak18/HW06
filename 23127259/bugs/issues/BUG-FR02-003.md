# BUG-FR02-003: Premature Account Lockout on Valid Login Attempt at N=2 Boundary

## Requirement
- **Specification Source:** EShop SRS §2 [FR-02] (Consecutive Failed Login Counter & Reset Semantics)
- **Specification Clause:**
  > "The lockout threshold is 3 CONSECUTIVE failed login attempts. An account with 2 failed attempts ($N=2$) must remain unlocked. If the user submits correct credentials on the 3rd attempt, login must succeed (HTTP 200 + JWT) and reset the consecutive failure progression to 0."

## Related Test Case
- **Test Case ID:** `FR02-HUM-003` (Student-Designed Human Extension)
- **Traceability Path:** `06 – Human Extensions / FR02-HUM-003 – Consecutive Failure Reset at N=2 Pre-Lockout Boundary`

## Environment
- **Target Host:** `http://localhost:3000`
- **Component:** EShop Login Controller / Failure Counter Logic
- **Runtime:** Node.js v20.x, SQLite3
- **Runner:** Newman v6.2.2 / Python requests

## Preconditions
- A registered user account exists with 0 prior failed login attempts.

## Reproduction Steps
1. Verify account authenticates with correct credentials (baseline check).
2. Submit Attempt #1 with incorrect password $ightarrow$ Returns HTTP 401 Unauthorized ($N=1$ failure).
3. Submit Attempt #2 with incorrect password $ightarrow$ Returns HTTP 401 Unauthorized ($N=2$ failures; pre-lockout boundary).
4. Submit Attempt #3 with the **CORRECT PASSWORD**:
   ```bash
   curl -s -X POST http://localhost:3000/api/login \
     -H "Content-Type: application/json" \
     -d '{"email": "user@eshop.com", "password": "CorrectPassword123!"}'
   ```

## Expected Result
- Attempt #3 is a valid authentication attempt. It must succeed with HTTP `200 OK`, issue a valid JWT token, and reset the failure counter to 0.

## Actual Result
- SUT returns HTTP `403 Forbidden`:
  ```json
  {
    "error": "Tài khoản đã bị khóa. Vui lòng thử lại sau."
  }
  ```
- The account is locked on the 3rd attempt even though valid credentials were submitted.

## Reproducibility
- **100% (Deterministic across Newman and Python test scripts)**

## Severity
- **HIGH**

## Severity Rationale
- Prevents legitimate users who mistyped their password twice from logging in on their 3rd attempt with their correct password. Causes premature lockout on valid credentials.
