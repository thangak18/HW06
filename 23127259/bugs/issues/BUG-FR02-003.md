# BUG-FR02-003: Correct Login Rejected After Two Consecutive Failures

## Requirement

- **Normative source:** EShop SRS §2, FR-02.
- **Oracle:** Each incorrect login increments the counter by exactly one, and the account locks only after three or more consecutive failed logins. Correct credentials after exactly two failures must succeed and reset the sequence.

## Related Test

- **ID:** `FR02-HUM-003` (student-designed extension after gap analysis)
- **Postman path:** `06 - Human Extensions / FR02-HUM-003 - Consecutive Failure Reset at N=2 Pre-Lockout Boundary`

## Environment and Preconditions

- Host: `http://localhost:3000`
- A fresh registered account begins with zero failures.
- Runner: Newman 6.2.2 and Postman Desktop 11.89.0.
- All requests include `X-Student-Id: 23127259`.

## Reproduction

1. Submit an incorrect password once.
2. Submit an incorrect password a second time.
3. Submit the correct password through the main `FR02-HUM-003` request.
4. Observe the response and failed assertion.

## Expected

- The third request succeeds with HTTP `200 OK` and issues a JWT.
- The consecutive-failure sequence resets.

## Actual

- The valid third request returns HTTP `403 Forbidden`.
- API body reports that the account is locked.

## Severity

**HIGH** - legitimate users are locked before the documented three-failure threshold.
