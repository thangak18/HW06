# BUG-FR14-004: Empty PUT Body Corrupts Existing Category Name to null

## Severity

**MEDIUM** — Data integrity defect; existing data is corrupted by a partial-update request.

## Requirement Source

- SRS FR-14: Category name is mandatory and must not be empty. The PUT update operation must not violate this invariant.
- API specification §3.4: `PUT /api/categories/:id` updates an existing category.

## Security Mapping

FR-14 mandatory-name/data-integrity rule. SEC-02 is JWT authentication and is not used as this bug's classification.

## Precondition

- Admin account is authenticated with valid JWT.
- A valid category exists (created earlier in the test).

## Reproduction

1. Login as admin.
2. Create a category with name "EmptyPutTarget" (e.g., via `POST /api/categories`).
3. Capture the new category ID.
4. Send `PUT /api/categories/{id}` with empty body `{}`.
5. Verify via `GET /api/categories`.

## Expected Behavior

Either:
- Return a 4xx error (preferred, treating empty body as invalid input).
- OR preserve the existing name unchanged.

The original category name must NOT be erased, nulled, or replaced with empty string.

## Actual Behavior

The PUT request returns **200 OK**, but a subsequent GET confirms the category's `name` field was corrupted to `null`. The existing data is silently overwritten with an invalid value.

## Verification

Confirmed via Newman Run01 execution of TC-FR14-H05: the empty PUT body caused the previously-set name to become `null` in the API-visible state.
