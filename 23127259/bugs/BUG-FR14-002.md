# BUG-FR14-002: Missing Input Validation — Empty/Null/Whitespace Names Accepted

**Bug ID:** BUG-FR14-002  
**Feature:** FR-14 – Category Management CRUD  
**Student:** Nguyễn Tấn Thắng (23127259)  
**Severity:** 🟡 **MEDIUM** (Data Quality)  
**Priority:** P2  
**Status:** CONFIRMED  
**Confirmation Date:** September 2, 2026

---

## Summary

The `POST /api/categories` endpoint accepts and stores category names that are empty strings (`""`), `null`, `undefined` (missing key), and whitespace-only (`"   "`). This allows creation of meaningless or invisible categories that corrupt the data model.

---

## Reproduction Steps

1. Login as admin: `POST /api/login` with admin credentials
2. Send: `POST /api/categories` with body `{ "name": "" }`
3. **Observed:** HTTP 200 with `{ "message": "Category created", "id": <n> }`
4. **Expected:** HTTP 400 Bad Request with validation error
5. Send: `POST /api/categories` with body `{ "name": null }`
6. **Observed:** HTTP 200 — null stored in database
7. Send: `POST /api/categories` with body `{}`
8. **Observed:** HTTP 200 — undefined (null) stored

---

## Root Cause

In `server.js` line 250-254, the endpoint destructures `name` from `req.body` and directly passes it to the SQL INSERT without any validation:

```javascript
app.post("/api/categories", authenticateToken, (req, res) => {
  const { name } = req.body;   // No validation!
  db.run("INSERT INTO categories (name) VALUES (?)", [name], function (err) {
    // ...
  });
});
```

## Recommended Fix

```javascript
app.post("/api/categories", authenticateToken, (req, res) => {
  const { name } = req.body;
  if (!name || typeof name !== 'string' || name.trim().length === 0) {
    return res.status(400).json({ error: 'Category name is required and must be a non-empty string' });
  }
  // ... proceed with INSERT
});
```
