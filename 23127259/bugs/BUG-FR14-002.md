# BUG-FR14-002: Empty/Null/Missing/Whitespace Category Names Accepted Without Validation

## Severity

**MEDIUM** — FR-14 requirement violation; data integrity defect.

## Requirement Source

- SRS FR-14: "Category name is mandatory and must not be empty."
- SRS FR-14: "Add/View/Delete Category" operations must enforce valid category names.

## Security Mapping

FR-14 mandatory-field/data-integrity rule. SEC-02 is JWT authentication and is not used as this bug's classification.

## Precondition

- Admin account is authenticated with valid JWT.

## Reproduction

1. Login as admin `admin@eshop.com` / `Admin123!`.
2. Obtain admin JWT token.
3. For each test case, send `POST /api/categories` with an invalid name:

| Test | Body | Expected | Actual |
|---|---|---|---|
| Empty string | `{"name":""}` | 4xx rejection | 200 + persisted |
| null value | `{"name":null}` | 4xx rejection | 200 + persisted |
| Missing key | `{}` | 4xx rejection | 200 + persisted |
| Whitespace | `{"name":"   "}` | 4xx rejection | 200 + persisted |

## Expected Behavior

The API must reject category creation when the `name` field is empty, null, missing, or whitespace-only. Any 4xx status is acceptable; the key requirement is that **no invalid entity is created**.

## Actual Behavior

All four invalid-name cases return **200 OK** with a persisted entity. The API accepts empty string, null, missing key, and whitespace-only names without validation.

## Verification

After each failed POST, a subsequent `GET /api/categories` confirms the invalid entity was created and persists across requests.
